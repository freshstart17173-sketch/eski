--------------------------------------------------------------------------------
1. WHAT ESKI IS
--------------------------------------------------------------------------------
eski is a file format + web app for comics with a soundtrack. One ".eski" file
(a plain zip) holds the page images, the audio, and the manifest that maps audio
to pages. Turn a page and the music follows. Also supports user-triggered
"one-shots" (per-page sounds for dubbing/SFX).

Three apps, all vanilla JS, NO build step, NO frameworks. Only runtime dep is
JSZip 3.10.1 from cdnjs. pdf.js 3.11.174 is lazy-loaded from cdnjs for PDF import.
- index.html    = the LIBRARY, and the HOME PAGE (grid of eskis from library/)
- read.html     = the READER (open + read an .eski)
- composer.html = the COMPOSER (author/edit an .eski)
- spec.html     = the format spec (mostly text; hidden from nav, linked in footer)

3. HARD RULES / CONVENTIONS / GOTCHAS  (violate these and things break)
--------------------------------------------------------------------------------
* Vanilla JS only, no bundler, no framework. Each app is ONE self-contained HTML
  file. New CDN libs only when a feature demands it (JSZip, pdf.js).
* GNOMON FONT: the wordmark font is a base64 woff2 @font-face. It lives literally
  in spec.html. The other 3 HTML files carry a "/*FONTFACE*/" placeholder that a
  node one-liner replaces with spec.html's @font-face block. If you rewrite a
  whole HTML file, re-inject the font:
    node -e "const fs=require('fs');const src=fs.readFileSync('spec.html','utf8');
    const m=src.match(/@font-face\{[\s\S]*?format\('woff2'\);\n  font-display:swap;\n\}/);
    let s=fs.readFileSync('read.html','utf8');
    fs.writeFileSync('read.html', s.replace('/*FONTFACE*/', m[0]));"
  (node is at "C:\Program Files\nodejs\node.exe" on this machine; the `node`
  alias may not be on PATH in the Bash tool — use the full path or add to PATH.)
* ICONS: each page inlines a small `const ICONS = {name: "<svg inner>"}` map
  (Lucide v1.25.0, ISC license) + a paintIcons() that fills every [data-ico]
  element with an <svg class="ico">. Buttons keep their title text. To add an
  icon, curl https://unpkg.com/lucide-static@1.25.0/icons/<name>.svg and paste
  the inner markup into the map.
* SERVICE WORKER STALENESS: sw.js is now network-first for HTML (deploys land on
  a normal reload) and cache-first for assets (CACHE='eski-v4'). BUT an already-
  installed OLD worker keeps controlling the page until its next navigation, so
  during local dev after editing you often must unregister the SW or reload twice.
  In the smoke tests we set serviceWorkers:'block' to avoid this entirely.
* demo.eski is fetched by filename and is owner-swappable; NEVER hardcode its
  contents. It is intentionally absent from the repo. The reader also accepts
  ?read=<relative-path> to open a specific file (used by the library links).
* DISCORD invite is https://discord.gg/UFNpnHAbD (DISCORD const in index.html,
  static hrefs in read.html header/footer). composer/spec have no discord link.
* BUTTONS DO NOT INHERIT THE PAGE FONT. Every page needs
  button,input,select,textarea{font-family:inherit;font-size:inherit} or
  button-based UI (the library's .cover cards) silently renders in Arial.
* READER-SIDE OVERRIDES (reading mode, playback mode, direction, crossfade,
  one-shot loop) change what the reader DOES but must NEVER mutate the manifest.
  The composer writes exactly what the author authored. Smoke tests assert this.
* POSITION MEMORY is keyed by comic TITLE (localStorage 'eski-pos-<title>').
  Known weakness: two comics with the same title share a saved page. (backlog fix)
* VERCEL has no directory autoindex, so library.html's "just drop files in
  library/" auto-listing does NOT work there — on Vercel you must ship a
  library/index.json. Locally / on autoindex hosts it works with zero config.
* DON'T commit .eski files to git (repo bloat + Vercel bandwidth). Host media on
  Cloudflare R2 (free egress) and point library/index.json at R2 URLs.
* JS SCOPE GOTCHA when testing: top-level `let`/`const` (cState, os, zoom, audio,
  oneshotsFor...) ARE reachable by bare name inside Playwright page.evaluate()
  (they live in the global lexical env). They are NOT reachable via `window.` for
  let/const; only `function foo(){}` declarations attach to window. The in-app
  browser's javascript_tool eval canNOT see bare let/const at all — use
  window.<fn> there and it only sees function declarations.
* Copy style: lowercase headlines/labels, terse, plainspoken. Say "an .eski",
  never "a .eski". NO em dashes anywhere. Keep the reader minimal.

4. FILE FORMAT (manifest v2)  — full spec in spec.html
--------------------------------------------------------------------------------
An .eski is a plain zip:
  001.png ... 047.png        pages, sorted by filename (numeric-aware)
  audio/                     the audio files
  .eski/cover.png            optional cover copy (reader samples it for the tint)
  .eski/manifest.json        the map

manifest.json (version 2):
{
  "version": 2, "created": "...ISO...", "app": "eski",
  "meta": { "title": "", "creator": null, "description": null,
            "direction": "ltr" | "rtl", "cover": "001.png" },
  "player": { "volume": 80, "crossfade": 1.0, "loopMode": "loop" | "next",
              "playbackMode": "sync" | "playlist", "readingMode": "pages" | "scroll",
              "oneshotLoop": false },
  "tracks": [
    { "id":"t1","title":"","source":"local","file":"audio/01-x.mp3",
      "type":"music","volume":100,"sync":{"from":3,"start":0} },
    { "id":"t2","title":"quiet","source":"local","file":null,
      "type":"silence","volume":100,"sync":{"from":5,"start":0} },
    { "id":"o1","title":"line one","source":"local","file":"audio/03-o1.mp3",
      "type":"oneshot","volume":100,"sync":{"from":4,"start":0} }
  ],
  "pages": { "count": 7, "naming": "auto" }
}

Rules:
- TYPES: "music" and "silence" own PAGE RANGES; "oneshot" does NOT (reader triggers it).
- OWNERSHIP: sort music/silence by sync.from; a track owns pages from its trigger
  to the page before the next trigger (last owns to the end). Pages before the
  first trigger are silent. One-shots are excluded from this computation.
- QUEUES: music tracks sharing a sync.from form a queue in manifest order; when
  one ends the next continues within the same range; after the last, loopMode
  decides restart vs quiet.
- ONE-SHOTS sharing a sync.from form an ordered list (manifest order) the reader
  walks with a cursor. sync.start = in-point offset. sync.end (optional, music)
  = out-point. player.oneshotLoop = default for cursor wrap.
- v1 files with streaming tracks ("source":"yt"/"sc") load but those tracks are
  unavailable/silent and dropped on re-export. Plain cbz/zip open as silent comics.

5. READER  (read.html) — how it works
--------------------------------------------------------------------------------
Boot: sets theme, paintIcons, reads ?read= (else demo.eski), fetch -> JSZip ->
comicFromZip -> openComic. body gets .needs-gesture until first user interaction
(browsers hold audio).

LAZY LOADING: pages keep their JSZip entry and decompress on demand
(ensurePageUrl) with prefetchAround(+/-3). Scroll mode uses an IntersectionObserver
to load pages as they approach the viewport.

AUDIO ENGINE (const audio): dual <audio> elements a/b for equal-power-ish
crossfades (fade()). No global play... EXCEPT space now pauses/resumes the
soundtrack (owner override of the old "no pause" rule). audio.resolve(track)
lazy-decompresses audio. loadSeq guards against stale async loads on fast turns.
- checkPageTrack(): on page change picks the queue for audioPage() and plays
  its first track (or continues if mid-queue). onTrackEnd() advances the queue /
  loops / goes quiet per loopMode. Silence tracks fade the previous out.
- audioPage(): in spread mode the LEFTMOST visible page decides the audio.
- Playlist mode (effPlayback()==='playlist'): tracks advance on 'ended',
  independent of page turns; page bar still shows ranges.

READING MODES: effReadingMode() = 'pages' | 'scroll' (file default + reader
override). Pages mode = one page (or two in spread). Scroll mode = vertical
scroller; current page = the one crossing the viewport midline.

PAGE ZOOM/PAN (pages mode only): wheel zooms toward cursor (1x-5x), drag pans
when zoomed, double-click toggles, turning the page resets. Click-zones disable
while zoomed. State: zoom/panX/panY, applyZoom(), zoomAt(), resetZoom().

DIRECTION: isRTL() flips arrows, click zones, spread pairing, page bar direction.
TINT ("colour match"): applyTint() samples the cover hue -> --hue/--tintsat CSS
vars; toggleable; off = neutral grey. Dark theme derives from the same vars.

FULLSCREEN FOCUS (toggleFocus): real requestFullscreen on documentElement, hides
all chrome; mousemove "peeks" the player bar; settings popover stays usable.

DEEP LINKS: #comic-title/page=N applied on load; hash updated via replaceState
on nav. slugify(title) keys it.

ONE-SHOTS (const os): os.list = one-shots for the current page (reset on page
turn, monophonic os.el channel). Keys: DOWN = next, UP = previous (no wrap unless
loop). shift+space = pause/resume the current one-shot. Corner indicator (#os-hint)
shows only when the page has one-shots: speaker + "n/total" + up/down taps, and a
.playing class (pulsing speaker + #os-prog progress bar) while audio plays.
effOsLoop() from settings.osloop (seeded by player.oneshotLoop). First-run
tutorial popup (#tut-os). Hotkeys panel (#keys-panel) toggled by "?" or #keys-btn.

CONTROLS: player bar (bottom): now-playing, page bar (colored per track) + song
progress bar, page jump, spread/focus/new-file/hotkeys/settings/mute/volume.
The old < > nav arrow BUTTONS were removed; page turns via click zones + arrows.
Settings popover (#settings): colour match, reading, playback, direction,
crossfade (file/fixed/off), one-shots loop. Dark-mode toggle is currently a
header button (contrast icon) — see PENDING #0.

HOTKEYS: arrows/click = pages; space = soundtrack pause; down/up = one-shots;
shift+space = one-shot pause; s spread; f focus; m mute; d dark; ? hotkeys; esc.

6. COMPOSER  (composer.html) — how it works
--------------------------------------------------------------------------------
STATE: cState = { pages:[{name,blob,url,thumb}], tracks:[{tid,aud,type,title,
from,start,volume}], meta:{title,creator,description,direction}, player:{...},
coverIndex }. audioStore[aud] = {blob,url,fileName,peaks,duration}. audioPool =
ordered aud ids for the bay. osBlocks = Set of pages with an (even empty) one-shot
block. undoStack/redoStack snapshot (JSON) of tracks/meta/player/coverIndex.

LAYOUT: layered surfaces --bg-0..--bg-3 + shadows (NOT the reader palette; the
composer commits to depth over brand purity, by owner request). Header: add media,
add folder, open .eski, settings, export, dark. Left = MEDIA BAY. Center = STAGE
(preview on top, timeline below). Right = settings DRAWER (toggle).

MEDIA BAY: images (page thumbnails) + audio blocks (with mini waveforms). Search
box + filter (all/images/audio/unused) + audio sort (added/name/duration). Zoom
+/- for image chips. Blocks are draggable (dataTransfer text/eski-img, /-aud).
Import: "add media" (images/cbz/pdf/audio), "add folder" (webkitdirectory input +
recursive folder DROP via readEntryTree), "open .eski" (round-trip edit).

TIMELINE has TWO modes (modeswitch): 'sound' and 'pages'.
- SOUNDTRACK MODE: a ruler + a page-range row (one card per trigger page, with a
  thumbnail) + track lanes. Bands: drag the top GRIP to move the trigger page
  (snaps); drag the BODY to SLIP the in-point (waveform translates, pxPerSec
  scales with zoom); 2s scrub preview on release. Queues stack in lanes. Minimap
  zoom/pan bar with handles; "fit" zooms to the whole comic; ctrl+scroll zoom,
  shift+scroll pan, ctrl+shift+scroll = lane height. Selecting a band shows a
  compact CLIPBAR (name, volume, preview 2s, +queue, remove) in the toolbar.
  "add silence" button (sound mode only). High-res waveforms (~120 buckets/sec).
- PAGES MODE: every page as a thumbnail card (reorder by drag, remove via x,
  drop images to add). Page zoom +/-. Each page can hold ONE one-shot BLOCK
  (badge on the card with count); a draggable "one-shot" TOOL in the toolbar
  drops onto a page to create the block; clicking the badge opens the QUEUE PANEL.

ONE-SHOTS (composer): tracks with type 'oneshot'. oneshotsFor(page) = ordered
list. QUEUE PANEL (#qp, currently a CENTER MODAL): lists one-shots as reorderable
chips, drag audio from the bay to append, x removes, "remove this block" clears.
moveOneshotBefore() handles reorder/move. Export packs one-shot audio + writes
type:"oneshot"; soundtrack lanes ignore one-shots (soundTracks() filter).

EXPORT (exportEski): packs pages as NNN.ext, unique audio once (music+oneshot),
writes manifest v2 + cover, downloads. Opus/WebCodecs compression was REMOVED
(too slow) — sources pack as-is.

TRASH BAR (#trash-bar): drag any bay block / page card / timeline band toward it
to delete (appears mid-drag, red when hovered). LOADING overlay (#loading) on
import/export. Undo/redo (ctrl+z/y), copy/paste (ctrl+c/v), delete, esc.

--------------------------------------------------------------------------------
14.1 TERMINOLOGY (use these words, nothing else)
--------------------------------------------------------------------------------
BASE        the comic itself: pages, cast, slots, consent. Owned by the author.
SLOT        an authored void on a page: a dialogue line or an SFX hit. No audio.
VO          one voice actor's full set of clips for ONE character on one base.
SOUNDTRACK  one musician's music/silence tracks + audio for the base's SFX slots.
MIX         base + one VO per character (or muted) + one soundtrack (or none).
            The thing a reader actually loads and a view is logged against.
CANONICAL   the author-pinned default mix. Required at publish.

Retired words: "cut" (now MIX), "performance" (now VO), "sound package" (now
SOUNDTRACK), "one-shot" stays only as the reader-engine/manifest term.

--------------------------------------------------------------------------------
14.2 DECISIONS (settled, do not relitigate)
--------------------------------------------------------------------------------
D1  ORIGINAL WORK ONLY. eski hosts comics whose author is on the platform and
    can actually grant consent. No fan-dub-of-third-party-manga business. The
    copyright/DMCA exposure is what kills this project otherwise. (Absolute
    Batman in library/ is local test content only, never published.)
D2  BASE IS IMMUTABLE ONCE PUBLISHED. There is no version 2 of a comic. Only
    errata: swap a page IMAGE in place, same page count, same slot ids. Reason:
    any reflow destroys every VO and soundtrack built against it. This kills the
    comic_versions table, the slot-migration story, and the orphan problem all
    at once. If a comic genuinely needs restructuring it is a NEW base.
D3  FULL COVERAGE VOs ONLY. A VO stays draft until every line slot for its
    character has a clip. Publish is blocked below 100%. Composer shows a
    coverage meter. Kills partial-VO ranking abuse.
D4  NO LEADING DEAD AIR. Enforced at ingest, not left to the VA. decodePeaks
    already decodes every file; find first sample above the noise floor and
    auto-set trim_start_ms there. lead_ms clamped to 0-250. VA nudges inside
    that window only.
D5  NO AUTHOR APPROVAL GATE. VOs and soundtracks publish directly. Readers
    combine freely. Quality is sorted by popularity; abuse is handled by reports
    to mods. MODS = THE OWNER, SOLE MODERATOR, confirmed. Author still pins a
    canonical mix, which is
    also the cold-start default when nothing has plays.
D6  CONSENT, TWO AXES, THREE MODES EACH:
      voice_consent  : closed | allowlist | open
      music_consent  : closed | allowlist | open
    Allowlist is per-axis, per-user. Goal is that authors run open (more
    exposure, and payouts later), but closed/allowlist exist.
D7  REVOCATION IS PROSPECTIVE. Flipping open -> closed does NOT kill existing
    published VOs/soundtracks. Only a moderator takedown removes work. Otherwise
    nobody invests effort in a dub.
D8  PAYOUTS AND SPLITS: DEFERRED. Not built, not designed. BUT log views and
    resolved contributors from day one of multi-user; attribution history cannot
    be backfilled.
D9  CONTRIBUTORS SEE THE FULL ART. Accepted risk. Consent gates attaching work,
    not redistribution. No technical fix exists.
D10 COMPOSER MODES. See 14.4. Musicians see music + SFX. VAs see dialogue, and
    ALSO SEE SFX SLOTS READ-ONLY (they hear canonical SFX for timing, they
    cannot fill them). ASSUMPTION FLAG: "let VOs see the sfx" was read as
    read-only context. One flag flips it to fill rights if that was wrong.

14.3 THE FOUR PEOPLE
--------------------------------------------------------------------------------
READER. Opens library (home). Picks a comic. Gets the canonical mix by default,
  or opens the mix picker: choose a VO per character (or mute), choose a
  soundtrack. VO preview lets them audition before committing (see 14.6). Read
  loop is unchanged: pages turn, music follows, down/up walks the lines.
  The reader never knows it assembled three sources.

AUTHOR. Imports pages (existing composer import). Then two author-only jobs:
  CAST, e.g. [{key:"aiko", name:"Aiko"}] - only the author knows who speaks.
  SLOTS, marking every dialogue bubble and SFX hit: page + order + kind +
  cast key + bubble rect + optional attachTo/offset. No audio attached.
  Then sets consent, publishes, pins a canonical mix.

MUSICIAN. Browses bases where music_consent allows. Sees page thumbnails, page
  count, slot layout for timing. Drags music, sets trigger pages, fills the
  author's SFX slots. Exports a soundtrack bound to that base.

VOICE ACTOR. Browses bases where voice_consent allows. Picks ONE character.
  Sees only that character's line slots, in page order. Per slot: a CROP of the
  bubble rendered from the page image (this is why rect exists), the previous
  line played back for pacing, drag-and-drop import of externally recorded audio,
  trim, retake. Publishes at 100% coverage.
  NOTE: this is why section 13's "no captions/transcripts" holds. Correct for
  readers (the text is on the page). The VA gets the bubble crop instead of a
  transcript field. Costs nothing, art is already loaded.

STORE OBJECT KEYS, NEVER FULL URLS. Every *_key column holds the R2 path
("a/3f9c2e/01.mp3"), and the reader builds R2_PUBLIC_BASE_URL + '/' + key at
request time. This keeps the media host a one-variable decision: ship on the
rate-limited pub-<hash>.r2.dev dev domain now, move to cdn.eski.lol whenever
the nameservers land on Cloudflare, flip one env var, migrate zero rows.
Storing full URLs turns that same switch into a rewrite of every media row.
(Nameserver note: an R2 custom domain REQUIRES the eski.lol zone on Cloudflare.
That is the only real reason to move it. If you do, the apex and www records
must stay DNS-only/grey-cloud pointing at Vercel; proxying Cloudflare in front
of Vercel stacks two CDNs. Env vars are unaffected by any DNS change.)

Three things worth defending:
- SLOTS ARE REFERENCED BY ID, NEVER PAGE INDEX. Index-based references break the
  moment anything shifts. (D2 means nothing shifts, but ids cost nothing and
  survive the day D2 gets revisited.)
- MIXES ARE UPSERTED BY combo_hash. Readers combine freely (D5), so a mix row is
  materialized on demand, not curated. Popularity then accrues per VO, per
  soundtrack, AND per whole combination independently.
- view_contributors IS WRITTEN AT VIEW TIME, DENORMALIZED. Mix composition
  changes later. Payout math must never re-resolve history.

14.6 LOADING
--------------------------------------------------------------------------------
  GET /api/mix/:id  ->  base .eski url + resolved track list (audio URLs)

One request, then:
- PAGES: base stays a ZIP. Reuses the whole existing path: JSZip, lazy per-page
  decompress, prefetchAround(+/-3). Already built, do not touch.
- AUDIO: individual R2 objects, NEVER zipped. A VO zip forces downloading all
  200 lines before page 1 renders. Individual objects prefetch per page the way
  images already do. Lines are 50-200KB.

THE REASON THIS IS CHEAP: audio.resolve() (index.html) already returns
track.url when set and only falls back to a zip entry. Platform tracks simply
arrive carrying a url. The reader audio engine needs ZERO structural change.
The mix resolver is ~150 lines of fetch + manifest merge in front of the
existing comicFromZip/openComic.

VO PREVIEW: generated at ingest, not assembled at browse time. Take the VO's
FIRST 3 SLOTS in the comic, concatenate to one clip, store as preview_key.
Deterministic, needs no "densest page" computation, and the opening lines are
what a reader wants to audition anyway. Browsing a VO then costs one small
fetch instead of resolving a whole mix.

EXPORT STILL WORKS: flatten a mix to a portable single .eski via the existing
exportEski. Offline/sharing snapshot, no format schism.

--------------------------------------------------------------------------------
14.7 VOLUME NORMALIZATION
--------------------------------------------------------------------------------
Measured at INGEST, reusing composer's decodePeaks (it already runs
decodeAudioData for waveforms, so this is nearly free). Store a gain. Never
touch samples, never re-encode: there is no encoder left (opus was removed).

NORMALIZE PER VO / PER SOUNDTRACK, NOT PER CLIP. Per-clip is the trap: a
whisper and a scream both land at -16 LUFS and the performance is destroyed.
Compute ONE gain from the artist's aggregate loudness. That matches VA to VA
and soundtrack to soundtrack while preserving dynamics inside each one.

TWO TARGETS, NOT ONE: dialogue ~-16 LUFS, music ~-20 LUFS. Music sits under by
construction, so the duck has less work to do and pumps less.

TRUE PEAK: after gain, check peak; if >0.99 clamp the gain down.

RUNTIME CHAIN:
  clip gain (manual) x vo/soundtrack norm x user volume x mute -> element.volume
                                                              -> duckGain node
                                                              -> peaking EQ
                                                                 400Hz, 2kHz
trackGain() in index.html is the single choke point; the norm multiplies there,
one line, and covers soundtrack and one-shots both.

14.10 KNOWN BLIND SPOTS (accepted or open)
--------------------------------------------------------------------------------
- Steps 1-2 make eski LOOK like a platform long before step 8 makes it BEHAVE
  like one. Fine while it is one user. Do not announce at step 2.
- Recording quality floor: MediaRecorder is webm/opus and iOS Safari is quirky;
  untreated bedroom audio next to produced music sounds broken. D4's ingest pass
  is the right place to also high-pass and check the noise floor, and warn.
  Otherwise the duck and EQ get blamed for problems they cannot fix.
- Line pacing: a VA records in isolation and the reader triggers manually, so
  delivery can feel disjointed. Mitigation lives in the booth (play previous
  line, show the page), not in the format.
- SFX timing chicken-and-egg: a musician filling SFX slots that attach to a line
  cannot hear that line if no VO exists yet. Either score against canonical, or
  attach-offsets get authored blind. Decide before building SFX-attach (step 10).
- Popularity ranking is gameable and rich-get-richer. Irrelevant at one user.
- Reports need a mod queue eventually. Table is enough for now, skip the UI.
- Storage: a 40-page comic + ~200 lines x 3 VOs + a soundtrack is roughly
  200-400MB. R2 storage is pennies, egress free. Not a constraint.
- Splits (D8) are the first thing contributors will ask about. The data model
  makes it answerable; it does not answer it.

================================================================================
15. DIALOGUE MODEL  (how comic dialogue actually maps onto slots; 2026-07-25)
================================================================================
Worked through the real conventions of comic lettering and what each one demands
of the schema, the reader engine, and the composer. Section 14's schema block is
already updated to match. Decisions here are settled unless marked OPEN.

--------------------------------------------------------------------------------
15.1 THE CENTRAL RULE: A SLOT IS A RUN OF SPEECH, NOT A BALLOON
--------------------------------------------------------------------------------
Twenty consecutive thought bubbles from one character on one page are ONE slot,
not twenty. A slot ends when the speaker changes, or when the page ends. A run
that spills onto the next page becomes two slots, one per page, because
one-shots are page-scoped and reset on a page turn.

The author marks WHO SPEAKS AND IN WHAT ORDER. Nothing else. A page with 30
balloons is often 5 or 6 slots.

Consequences, all simplifications:
- rects is OPTIONAL. The VA sees the page and knows they are Aiko on run 3.
  The author draws boxes only to disambiguate a genuinely confusing page.
- "linked balloons" (one sentence split across two balloons) is not an edge
  case at all. It was never two things.
- unison (one balloon, several tails) is NOT a multi-cast slot. It is two
  slots chained at offset 0. No array column needed.
- authoring effort drops enormously, which is the real reason this is right:
  the owner has to mark every page of every comic by hand.

--------------------------------------------------------------------------------
15.2 CHAINS ABSORB EVERY OVERLAP CASE
--------------------------------------------------------------------------------
Section 13 gave SFX an attach_to_slot_id + offset_ms. GENERALIZE IT TO EVERY
SLOT. Any slot may hang off any other. The reader's manual cursor exposes only
CHAIN HEADS (slots with no parent); one keypress fires a head and everything
attached to it, scheduled against its real start time.

That single mechanism covers:
  interruption (B starts before A ends)   crosstalk / people talking over
  unison (offset 0)                       a bleep landing over a word
  laughter or a gasp under a line         SFX landing on a punch
  a music cue firing off a specific line  (see 15.5)

THE MODEL IS UNCHANGED. Still exactly two triggers: page-triggered and
user-triggered. A chain is ONE user trigger.

COST: this requires POLYPHONY in the reader. os.el is currently a single Audio
element, so two voices cannot sound at once. A small pool of elements replaces
it. This is the one unavoidable engine change and it is already in the backlog.

--------------------------------------------------------------------------------
15.3 BALLOON STYLE IS NOT MODELLED
--------------------------------------------------------------------------------
Thought vs whisper vs shout vs radio vs telepathy: NO style enum, no per-slot
picker. Rejected as busywork for the author and noise in the schema.
Instead:
  - a short standing reminder in the VO booth that balloon shape carries
    delivery, and the art already says which is which
  - pages.note: optional author direction for a whole page ("this scene is
    a phone call", "she is barely conscious here")
  - LATER, optional: built-in reader effects (a radio filter and so on). Store
    nothing for it now. A VA performing it is usually better than a filter.

--------------------------------------------------------------------------------
15.4 FILLER VOs (the timing-reference problem)
--------------------------------------------------------------------------------
A VA often plays several characters, and should be encouraged to record scratch
"filler" for the OTHER characters in a scene so later VAs have something to time
against. Without it, everyone performs into a vacuum and the scene never locks.

vos.filler = true means: hidden from reader mix selection, excluded from
rankings, but SURFACED IN THE BOOTH as a timing reference track. It does not
disturb the full-coverage rule (D3) because a filler VO is not competing.

A VA covering several characters simply submits several VOs. That already works.

--------------------------------------------------------------------------------
15.5 MUSICIANS GET CUES TOO
--------------------------------------------------------------------------------
Previously only the author could define SFX slots and only music could be
page-triggered. Both restrictions lift:
- soundtrack_tracks.trigger_slot_id: a music track can start when a specific
  LINE fires, not only when a page turns ("the theme swells when he says her
  name"). Still user-triggered, because the reader fires the line.
- soundtrack_cues: a musician can attach their OWN audio to any slot with an
  offset, without the author having pre-marked an SFX slot for it. The same
  table also fills author-defined SFX slots (slot_id set instead).

--------------------------------------------------------------------------------
15.6 THE REST OF THE CATALOGUE, AND WHERE EACH LANDS
--------------------------------------------------------------------------------
NARRATION        cast_members.kind='narrator'. Castable and dubbable, just
                 never has a balloon tail. First-person retrospective captions
                 are the character's own cast id.
BACKGROUND SOUND slots.trigger='page' on an sfx slot: it fires on page arrival.
                 This is page-triggered audio, the same class as music, NOT a
                 third ambient layer (which section 13 rejected and still does).
CROWD / WALLA    THE RULE: if a specific named character says it, it is VO. If
                 nobody does, it is SFX. Settles most attribution arguments.
LAUGHS, SCREAMS, GRUNTS, CRYING
                 VO, not SFX. It is that character's voice, and it counts
                 toward coverage, which is correct.
EFFORT NOISES with no balloon    sfx slot.
EXPLETIVES / GRAWLIX (@#$%!)
                 NOT solved in the mix. vos.explicit lets a VA deliver censored
                 or uncensored, and competing VOs already exist, so a clean dub
                 and a filthy dub are simply two VOs. Zero new machinery.
FOREIGN LANGUAGE Left entirely to the VA. They will read what is written.
                 No schema, no translation slots.
FLASHBACK / AGED VOICE / POSSESSION
                 A SEPARATE CAST MEMBER ("young aiko"). No schema change, and
                 it lets the author cast a different VA for it.
CHARACTER WHO NEVER SPEAKS       coverage counts SLOTS, not cast members, so a
                 silent character is simply skipped. Avoids a divide by zero.
MYSTERY SPEAKER  the author names the cast entry "???" . No schema.
SIGNAGE, ENVIRONMENTAL TEXT      not a slot.
BOLD / ITALIC EMPHASIS           nothing. The art carries it.
A PAGE WITH 20 RUNS              a reader-side auto-advance setting, which per
                 the section 3 rule must never touch the manifest.

--------------------------------------------------------------------------------
15.7 COMPOSER / BOOTH UI THIS IMPLIES
--------------------------------------------------------------------------------
1. Numbered reading-order overlay on the page, draggable to reorder. Order is
   the one thing only the author can get right and it is currently invisible.
2. Chain authoring: drag one slot onto another to attach it, plus an offset
   scrubber. This single control IS the SFX-attach UI, the crosstalk UI, the
   interruption UI and the music-cue UI.
3. Optional rect drawing, not required to author a page.
4. pages.note field.
5. Coverage meter counts line slots for one character, excluding sfx.
6. Booth: previous slot plays before recording, filler VOs available as
   reference, drag-and-drop import of externally recorded audio (D-list).

--------------------------------------------------------------------------------
15.8 OPEN / BUGS
--------------------------------------------------------------------------------
OPEN - SINGING. A sung line has to sit in the soundtrack's key and tempo, but
  the VA and the musician are independent contributors. This is the ONLY place
  where contributor independence genuinely breaks. Three options, undecided:
  forbid sung lines; treat singing as SFX owned by the musician; or accept that
  sung comics only work in an author-blessed canonical mix.
BUG - SPREAD MODE HIDES HALF THE DIALOGUE. refreshOneshots() builds os.list
  from audioPage(), and audioPage() returns only the leftmost visible page
  (rightmost in RTL). In a two-page spread the other page's lines cannot be
  triggered at all. Fix: merge one-shots from both visible pages in reading
  order. Pre-existing, unrelated to the pivot, will bite the first dubbed
  spread.
