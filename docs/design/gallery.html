How to read this

This is the visual companion to docs/CANON.md. Screens are the live mockup embedded via iframe (interact with them). Dialogs, menus and modals are authored panels floating on a grey stage — the layer the mockup can't show at rest. Every panel carries a caption: what it is, what triggers it, and its database binding. Use the Dark button to check both themes.

Two known cosmetic lags in the embedded screens: they still say “group” (renamed to server — a text-only pass is pending) and the Feed still says “follows” (now friends). The dialog panels below already use the new terms. “Desktop” everywhere means the web app in a wide browser — not a native build.

① Member colours — the one hue in the UI, proposed at 30

Chrome is black/white/grey; the only colour is a member’s per-server identity hue, shown only inside that server (chat bylines, Members rail, contributor chips, canvas-comment authors, board assignees) and never on a public profile or the Feed. Servers hold a lot of people, so the palette is widened from the original 6 to 30 evenly-spaced hues (--m1 … --m30), each with a light + dark pair. join_via_invite assigns the next free index and cycles past 30 — identity colour is a legibility aid, not a uniqueness guarantee at scale. These are a generated proposal for you to critique before they’re written into styleguide.html.

▸ Swatch shows the current theme’s hex. ▸ Chips above preview names rendered in each hue. ▸ Critique: enough separation? too saturated on dark? cap at 24 instead of 30?
