eski! format spec back to the reader

the .eski format

an .eski is a plain zip archive. rename it to .zip and look inside. any cbz reader opens it as a silent comic; an eski reader also plays the soundtrack.

v3 is being drafted

everything below describes manifest v2, which is what the reader ships today. v3 replaces the ownership rule with layers: audio stacks, so a rain bed can run the whole comic while the score changes underneath it and an effect fires on one page, and the transcript (characters, lines, directions) moves into the file so voiceovers can point at it. the model, the v3 manifest and the v2 migration are written up in SPEC.md at the root of this repository, which is the master document. this page follows once v3 lands in the reader.

zip layout
my-comic.eski ← a plain zip archive
├─ 001.jpg … 047.jpg ← the pages, sorted by filename
├─ audio/ ← the soundtrack, opus or mp3
├─ .eski/cover.jpg ← optional cover copy
└─ .eski/manifest.json ← which track plays on which page

pages are every image outside .eski/ and audio/, sorted by filename with numeric awareness (2.png before 10.png). readers must ignore __MACOSX/ and other junk entries.

manifest v2
{
  "version": 2, "created": "2026-07-21T12:00:00Z", "app": "eski",
  "meta": {
    "title": "", "creator": null, "description": null,
    "direction": "ltr", "cover": "001.png"
  },
  "player": {
    "volume": 80, "crossfade": 2.0, "loopMode": "loop",
    "playbackMode": "sync", "readingMode": "pages", "oneshotLoop": false,
    "duck": "medium"
  },
  "tracks": [
    { "id": "t1", "title": "", "source": "local", "file": "audio/01-x.mp3",
      "type": "music", "volume": 100, "gainDb": -3.2, "sync": { "from": 3, "start": 0 } },
    { "id": "t2", "title": "quiet", "source": "local", "file": null,
      "type": "silence", "volume": 100, "sync": { "from": 5, "start": 0 } },
    { "id": "o1", "title": "line one", "source": "local", "file": "audio/03-o1.mp3",
      "type": "oneshot", "volume": 100, "gainDb": 1.4, "duck": "inherit",
      "sync": { "from": 4, "start": 0 } }
  ],
  "pages": { "count": 7, "naming": "auto" }
}

meta

fieldtypemeaning
titlestringdisplay title. also keys the reader's position memory.
creatorstring or nullwho made it.
descriptionstring or nulla sentence or two.
direction"ltr" | "rtl"reading direction. rtl flips page order presentation, arrows, click zones, spread pairing, and the page bar. default "ltr".
coverstringfilename of the cover page. readers sample it for the ui tint.

player

fieldtypemeaning
volume0–100starting volume.
crossfadesecondsoverlap length when one track hands off to the next.
loopMode"loop" | "next""loop": a track repeats until the page changes. "next": it plays once and goes quiet.
playbackMode"sync" | "playlist""sync": the page drives the music. "playlist": tracks advance when a song ends, no looping, independent of page turns.
readingMode"pages" | "scroll""pages": one page (or spread) at a time. "scroll": pages stack in one vertical scroller; the page crossing the viewport midline is current. default "pages".
oneshotLoopbooldefault for whether the reader's one-shot cursor wraps at the ends. default false; the reader can override it.
duck"off" | "light" | "medium" | "strong"how far the soundtrack drops while a one-shot plays. omitted means "medium": ducking is on by default, including for files written before this field existed. the reader can override it.

readers may offer overrides for crossfade, playback mode, reading mode, direction, one-shot looping, and ducking. overrides change what the reader does, never what the file says: a re-export writes what the author put in the manifest.

tracks

fieldtypemeaning
idstringstable id, unique within the file.
titlestringshown in the player strip.
source"local"v2 audio always ships inside the archive.
filestring or nullpath inside the zip, under audio/. null for silence tracks.
type"music" | "silence" | "oneshot"music and silence own page ranges (below). one-shots do not: they are triggered by the reader (below).
volume0–100per-track gain, multiplied with the player volume.
gainDbdecibels, optionalloudness correction measured at export so every track arrives at a comparable level. music is measured per track; one-shots share one value across the file, so a whisper stays quieter than a shout. the audio itself is never re-encoded. omitted or 0 means no correction; readers clamp to -24..+12.
duck"inherit" | "off" | "light" | "medium" | "strong", optional one-shots only. overrides player.duck for this one sound, so an ambient effect need not shove the music aside the way a spoken line does. default "inherit".
sync.frompage number, 1-indexedthe trigger page. the track starts when the reader reaches this page.
sync.startsecondsin point: offset into the audio where playback begins.
sync.endseconds, optionalout point: the track is treated as finished here. omitted means the full length plays.
the ownership rule

a track starts on its trigger page and owns every page until the next track's trigger. the last track owns through the final page.

sort tracks by sync.from. a range runs from one trigger page to the page before the next trigger; the last range runs through the final page. pages before the first trigger are silent.

tracks that share a trigger page form a queue, in manifest order: when one finishes (naturally or at its out point) the next continues, still inside the same page range. after the last track in a queue, loopMode decides whether the queue restarts or goes quiet.

silence tracks

silence is not the absence of a track; it is a track with "type": "silence" and "file": null. it takes ownership the same way, which is how a soundtrack stops mid-comic and hands off cleanly, crossfade included.

one-shots

a "type": "oneshot" track does not own pages and does not play on a page turn. it belongs to its sync.from page, and the reader triggers it by key or tap (down = next, up = previous). one-shots sharing a page form an ordered list, in manifest order, walked by a cursor. good for dubbing (a voice line per panel) and for sound effects.

one-shots play over the page soundtrack. the cursor resets when the page turns, so a one-shot lives only on its page. player.oneshotLoop sets whether the cursor wraps at the ends. they pack like any other track (audio under audio/, referenced by file).

v1 compatibility

v1 manifests could reference streaming sources ("source": "yt" or "sc"). readers accept v1 files but treat those tracks as unavailable: they stay silent, get flagged in the ui, and are left out when the file is re-exported. local v1 tracks keep working. plain cbz/zip archives with no manifest open as silent comics.

deep links

readers may support #page=12 and #comic-title/page=12 in the url, where the title is lowercased with runs of non-alphanumerics as dashes. the link applies once a matching file is open.
